# Codex CLI 提示词：《西游记·大闹天宫》HTML / CSS / Canvas 动画短片

你现在是一个前端动画工程师、Motion Designer 和视频导演。

我要你使用 HTML + CSS + SVG + Canvas + JavaScript 制作一个《西游记·大闹天宫》主题的网页动画短片。

## 目标

- 分辨率：1920x1080
- 比例：16:9
- 帧率：30fps
- 时长：约 30 秒
- 风格：东方神话、国风、水墨、黑金红、史诗感
- 不要低幼卡通
- 不要欧美奇幻风
- 不要依赖 AI 视频生成模型
- 所有主要视觉效果必须通过网页代码生成

## 技术要求

- 使用 Vite
- 使用 TypeScript
- 可以使用 GSAP
- 可以使用 SVG
- 可以使用 Canvas
- 不使用 React，除非确有必要
- 所有动画必须由统一 Timeline 控制
- 页面加载后自动播放
- 固定 1920x1080 画布
- 禁止滚动条
- 动画必须支持通过 frame 或 time 精确定位
- 后续需要支持逐帧截图并通过 FFmpeg 合成为 MP4
- 不要依赖真实 setTimeout 累积误差

## 剧情结构

> 以下剧情目前只是初版占位，后续会继续调整。实现前以最新 storyboard.md 为准。

### Scene 01：云海天宫
0-5 秒

云海翻滚，远处天宫从云雾中出现，镜头缓慢推进。

### Scene 02：悟空登场
5-9 秒

孙悟空以剪影形式跃上白玉天阶，红色披风飘动，金箍棒出现金色光芒。

### Scene 03：天兵列阵
9-14 秒

大量天兵从天宫两侧出现并形成阵列，长枪指向悟空。

### Scene 04：金箍棒横扫
14-20 秒

悟空旋转金箍棒，产生金色残影、冲击波和粒子，前排天兵被击飞，画面震动。

### Scene 05：天宫震动
20-26 秒

巨大冲击波扩散，宫殿、云层和柱子震动，碎石和金色粒子飞散。

### Scene 06：结尾
26-30 秒

孙悟空站在云海与残破天宫前，镜头缓慢推近，双眼发出金光。
最后出现标题：
“大闹天宫”

## 视觉原则

- 孙悟空以黑色剪影 + 暗红披风 + 金色眼睛 + 金色金箍棒表现
- 天兵以简化 SVG / Canvas 图形表现
- 天宫采用中国传统宫殿轮廓
- 云海主要使用 Canvas
- 金箍棒残影、火花、冲击波、碎石使用 Canvas
- 建筑和角色主体优先使用 SVG
- 镜头运动通过 scene/camera transform 实现
- 必须有明显的景深层次和前中后景
- 动画避免廉价的普通 fadeIn/fadeOut
- 多使用 push-in、parallax、scale、mask reveal、flash frame、screen shake、motion trail
- 不要使用 emoji 或 Unicode 图标代替视觉元素

## 执行顺序

第一步：
先分析需求并创建项目结构和 storyboard.md。
不要马上实现完整 30 秒动画。

第二步：
实现 Scene 01。
运行项目并检查最终画面。
如果有视觉问题，直接修改。

第三步：
Scene 01 完成后再实现 Scene 02。
后续同理逐幕实现。

第四步：
所有场景完成后，增加统一 Timeline 控制。

第五步：
增加：

```js
window.renderFrame(frameNumber)
```

要求我传入任意帧编号时，页面都能准确渲染对应画面。
动画结果必须 deterministic。

第六步：
编写 Playwright 导出脚本：

- 1920x1080
- 30fps
- 输出 frames/frame-00000.png
- 一共输出 900 帧

第七步：
增加 FFmpeg 合成命令，将 PNG 序列输出为 H.264 MP4。

## 工作规则

- 每次修改代码后必须检查是否有 TypeScript、Vite 或浏览器运行错误
- 不要一次性写大量无法验证的代码
- 优先使用可维护的小模块
- 重复逻辑必须抽公共函数
- 不要为了动画效果引入大量第三方依赖
- 不允许修改与当前任务无关的文件
- 如果视觉效果不理想，优先调整构图、比例、动画节奏，而不是堆更多特效

## 视觉质量验收

不要只关注“能运行”，视觉质量和动画节奏是核心验收标准。

每完成一个场景，都要从以下角度自行检查：

- 构图是否像视频画面，而不是网页
- 是否有足够的前中后景层次
- 动画是否有明显节奏
- 是否有镜头运动
- 是否存在元素过小、过散、过于居中的问题
- 是否有明显廉价网页动画感
- 是否符合东方神话和国风视觉语言

发现问题直接修改，不要只告诉我问题。
